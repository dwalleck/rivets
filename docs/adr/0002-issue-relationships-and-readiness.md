# Separate workflow, readiness, and issue relationships

Rivets separates an Issue's lifecycle from whether work can start: Workflow State is Open, In Progress, or Closed; Blocked is derived only from direct explicit Blocking Dependencies whose prerequisites are not Closed; and Ready means Open, not Blocked, and selected by Assignment visibility. A Ready query selects unassigned Issues by default, one exact Assignee when requested, or all Assignments explicitly; secondary filters, ordering, and limits apply only after eligibility. Issue Relationship is the umbrella for distinct semantics: a Blocking Dependency points from a dependent to its prerequisite, Parentage gives an Issue one Epic parent without propagating blockedness, Related Association is symmetric, and Discovery Origin is directed provenance. We chose explicit concepts over a generic dependency graph and a Blocked workflow state because the generic model conflated lifecycle, work eligibility, hierarchy, provenance, and association.

## Consequences

An Assignee exclusively claims the next action but may be assigned before work enters In Progress. An Epic cannot close while it has non-Closed children. Workflow State, direct Blocked derivation, and Assignment-aware Ready queries are aligned with this decision. Remaining relationship slices enforce one Epic parent, expose Related Associations symmetrically, model Discovery Origin explicitly, migrate legacy relationship records, and make Claim/Release atomic.
